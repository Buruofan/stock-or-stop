# 囤货算盘 · Stock or Stop

> 下单前 30 秒，回答「这次买几套合适、会不会囤过头」的纯前端本地计算器。

**Stock or Stop** 帮你把「消耗速度 × 家里库存 × 效期 × 到货时间 × 价格优势」放进同一次计算，给出一个**购买区间**——而不是一句「值得买」。它把「多买的那部分到底算提前囤货、还是要扔掉」这件事，做成了看得见的可视化。

## 它解决什么问题

大促时「买 2 送 1」的真实决策是多变量的：家里还有多少？我多久用一次？有效期够不够用完？新货何时到？等待期间会不会断档？

大多数人只看**单价**，于是出现两类误判：

- **买少了** → 大促前断档，只能用日常价补货。
- **买多了** → 低价货在效期内用不完，过期扔掉，**便宜的单价被浪费反噬成更高的实际成本**。

这个工具把「用不完」这件事变成可视化的一根区间条。

## 核心概念：两个「剩余」不是一回事

| 指标 | 含义 |
|---|---|
| **下次大促时还剩** | 提前占用：占钱、占地方，但货还活着，**不算亏**（折扣够好甚至划算） |
| **到期时剩** | 硬损失：过期 = 一文不值，**才是真浪费** |

判断「会不会囤过头」，**只看后者**。

## 三层购买推荐（不是「合理区间」）

| 层 | 名称 | 含义 |
|---|---|---|
| ① | 撑到下次大促的最少 | 保守购买基准 |
| ② | 提前囤货段 | **提前买**，需**价格优势支持**才成立 |
| ③ | 效期上限 | 超过就是过期浪费 |

## 功能一览

- **主流程**：三场景消耗建模（按次 / 按体积 / 按件），30 秒出「买几套」的区间结论。
- **消耗引擎**：FIFO 连续时间模拟，支持**多批旧货**、**先到期先用**、**到货感知**（未到货不能提前用）。
- **套装比价**：按「到手价 ÷ 实际能用掉的量」排序——与主流程**同口径**。
- **囤货拼单分摊**：一大单买回来，按各自真正需要的量分摊货款。
- **计算方法**：用六条短说明解释消耗顺序、到货等待、多批库存、套装比价和两类赠品口径。
- **数据保鲜**：数据存本机 localStorage；放久了提示确认库存；过去的大促日期自动顺延。

## 技术特点

- **纯 vanilla JS + HTML + CSS，单文件，零依赖、零构建、零网络请求**
- 全部计算在本机完成，**不上传任何数据**
- 移动端可用；`localStorage` 本机持久化
- 用 Node + DOM 桩做零依赖的不变量回归测试
