## 囤货决策器：按用户反馈重构（2026-10-11）

> 本文保留当日演进过程，包含后来删除的方案。最终产品规格以 `docs/PRD.md` 和 `index.html` 为准。
用户反馈要点已全部落地（文件：`stockpile-demo.html`，仍为纯前端单文件）：

**信息架构调整（解决"主次不分"）**
- 首屏唯一主流程 → 「这次买几件合适」：库存件数 + 一件用多久 + 套装件数/价格 + 计划买几套 + 旧货到期日 / 新货到期日 / 下次大促日期
- 输出：大促时还剩几件（占钱占空间，≠亏）| 到期时剩几件（= 真浪费）| 建议购买件数与套数、够用下限 / 不浪费上限区间
- 资金机会成本降级为主结果里的 `<details>` 折叠补充（默认年化 3%，不再要求用户先填参数）
- 辅助区降为次级：套装比价 / 预售vs现货 / 拼单分摊（独立工具）；临期场景并入主流程（= 新货效期很短的输入）

**两处口径 bug 已修**
1. 旧货与新货效期分开输入（原代码把「旧货最早到期」当新货效期）
2. 推荐量与浪费上限统一走同一套 FIFO 消耗模拟（原 `ceil` vs `floor` 互相矛盾，默认值下出 1 件 vs 0 件）

**新增核心引擎**：`simulate(batches, r)` —— 按最早到期优先做连续时间消耗模拟，返回各批 `used/waste/end` 与任意时点剩余量。推荐量 = [minNeeded, maxNoWaste] 区间，取够用下限，受效期限制时改成 maxNoWaste + 显式提示。
- 比价改为「到手价 ÷ 实际能用掉的件数」，并共享主流程的"旧货让位天数"
- 预售vs现货纳入到货等待（断档天数）与件数差异

**验证方式**：Node + DOM 桩直接 eval 页面脚本，跑 192 组参数组合做不变量断言（不误报"不用买"、推荐量不越界、囤过头必须真有浪费等），全部通过。

## 第二轮：三场景消耗模型（同日）
用户反馈「一件用多久」不适用于护肤品多毫升组合，且预售vs现货无联动 → 重构：

- **三种消耗模型（场景切换，输入项各自不同）**：`count` 按次用（面膜，多久用一次 × 每次几份）｜`volume` 按体积用（护肤套装，每天 ml + **套装按「容量×数量」多行录入** + 赠品折算率，自动合计每套等效 ml）｜`pack` 按件用（一件用 N 天）。统一归一到「每天消耗量 / 库存量 / 每套量」，复用同一套 FIFO 模拟引擎。
- 每个场景独立保存输入（`state[scene]`），切换不丢数据；每个场景 2 个示例按钮（容易囤货 / 买多了浪费），比价工具的示例方案也随场景切换。
- **大促日期默认取下一个 618 / 双 11**（`nextSale()`：6-18 → 11-11 → 次年 6-18 取最近未来节点）。
- **预售vs现货改为双栏卡片**（不再挤在表格里），默认自动联动主流程：现货=主流程套装、预售=9折+等15天+赠品20元；改动某栏后该栏置为「已手动调整」并停止跟随，可一键「恢复联动」。
- 修了一个离散单位 bug：`minNeeded <= 0.05` 的容差对「件」太松（1 件用 30 天 vs 大促 31 天后被误判"不用买"），改为 `1e-6`，并对离散单位用 `minNeededShow = ceil(minNeeded)` 展示。
- 测试扩展到 3 场景 × 参数网格（192 组）+ 联动行为 + 单位标签切换，全部通过。

## 第三轮：体积场景可倒推 + 拼单改为囤货分摊（同日）
用户反馈两点，均已落地（文件仍为 `stockpile-demo.html`）：

**1. 按体积用：不让用户估「每天几 ml」，改为从已知信息倒推**
- 新增 `rateMode` 开关：默认 **「我知道一瓶能用多久」**（填 一瓶 ml + 够用天数 → 自动算出 ml/天，并在提示里回显「≈4 ml/天、一瓶能用 25 天」）；另一档是「我知道每天用多少」。
- 库存也支持 **瓶 / ml 双单位**（切换时保持物理量不变，`lastStockUnit` 记录上一次单位做换算），并按「最大正装 ml」自动给出「≈1.2 瓶」的提示；参考瓶容量 = 套装里最大的正装 ml（`volBottle()`）。
- **结果全部改成双口径表达**：`amtRef()` → 「1200 ml（≈2.4 瓶）」；小数量自动用分数（`bottleLabel` + `fracStr`，如 1/2 瓶、1/3 瓶、4/5 瓶）；小于 0.1 瓶干脆不换算（避免「0.04 瓶」）；指标卡主数值是「2.4 瓶」+ 副行「≈1200 ml」。

**2. 拼单分摊 → 真正的「囤货拼单」**
- 删掉电商购物车的满减/免邮逻辑。新模型：**一大单买回来（规格 × 数量，默认沿用主流程的套装规格 × 打算买的套数），几个朋友按各自真正需要的量分摊**，忽略邮费。示例即「3 瓶 500ml 正装 + 5 份 20ml 小样」。
- 单位随主场景联动（份 / ml / 件）；成员需要量可填 ml 或 瓶（volume 下）。
- 输出：每人需要量、占总量比例、应摊货款（按平均单价），并单独提示 **未被认领的余量**（默认发起人自留）或 **超额认领** 警告。
- 与主流程的联动：未手动改动时自动跟随（`gPackDirty` / `gMemberDirty`），切场景重置。

**顺带修掉一个口径不一致 bug（测试抓到）**：`simulate().remainingAt(D)` 原来是各批独立按 `b.start` 计算，忽略了「旧货没吃完前新货吃不上」的 FIFO 占位，导致「大促时还剩」与「到期时剩」互相矛盾（出现 到期剩余 > 大促剩余）。改为**用同一套 FIFO 规则把时间轴截到 D 重算**，两者自洽。

**小修**：`fmt()` 非整数金额统一两位小数（¥0.8 → ¥0.80）；`perU` 在 ml 场景读作「每毫升」；去掉几处嵌套括号（改为「，即 N 套」）。

**验证方式**：Node + DOM 桩 eval 页面脚本，新增不变量（到期剩余 ≤ 大促剩余、用量守恒、recQty = recSets × 每套量、拼单每人应付之和 = 认领量 × 均价、应付合计 ≤ 整单价、超额认领识别、瓶数表达边界、倒推 ml/天、大促日期为 6-18/11-11），共 **605 条断言全部通过**。

## 第四轮：四个逻辑问题 + 两个产品风险（同日）
用户逐条指出的问题，全部落地：

**逻辑修复**
1. **推荐整套却会过期**：推荐量改为在「套」这一层对齐（`maxSetsNoWaste = floor(不浪费上限/每套量)`、`minSetsNeeded = ceil(够用下限/每套量)`），并引入四种 `kind`：`none / fit / limited / unfit`。当 `maxSetsNoWaste === 0`（连 1 套都吃不下）判为 **unfit**，明确输出「这个套装规格不适合你；考虑小包装或拼单」，绝不再把 1 套标成建议量。
2. **断档天数单位错**：原来把「缺几件」直接当天数。改为看「到大促那天为止实际有货可用的天数」：`gapDays = ceil(sale − usedBySale/r)`（除以每天消耗速度），并加 1e-9 容差避免浮点误报 1 天。
3. **到货时间模拟**：`simulate()` 重写为**事件驱动、到货感知**——任何时刻只从「已到货且未过期」的批次里消耗最早到期的；未到货的货不能提前用。主流程新增「预计到货日」输入（默认今天）。修掉了「新货效期比旧货早时，预售断档被误判为 0 天」的问题。
4. **赠品「价值」与「实物量」分离**：体积场景赠品拆成 4 个输入——实收 ml、预计用掉 %、能否与正装合并计算（不同产品不并入用量）、估值 ¥（只用来抵减成本 → 净价 = 到手价 − 估值）。拼单大单里的赠品按**实收 ml** 分（不再按估值折算）。

**产品层面**
5. **语气去断语**：fit 时输出「合理购买区间：X ~ Y（N ~ M 套）」+ 取舍说明（靠下限=少占钱，靠上限=单价低但押更多钱），不再说「刚好合适 / 建议购买 N 套」。
6. **首屏减负 + 本机持久化**：localStorage 保存 `mode/state/offers`（key `stockpile-demo-v1`），刷新/重开都还在，复购用户不用重填；示例按钮提前到输入区上方（「30 秒快速开始」）；输入分三组 ①使用情况 ②想买的套装 ③关键日期；有效期/到货收进折叠 `<details>`（预填典型值）；新增「清空重新填」。count（面膜）仍是默认场景，预填即可看结论。

**移动端实测**：无头 Chrome 有 500px 最小窗宽（`--window-size` 会被钳制），初看以为页面被撑宽，实际是截图假象；用 390px iframe 验证布局正常。顺手做了两个防御性改进：比价/拼单表格包进 `.tbl{overflow-x:auto}` 滚动容器、去掉辅助区标题的 `white-space:nowrap`。

**验证**：`/tmp/t5.js` —— Node + DOM 桩 eval 页面脚本，**281 条断言全部通过**（含 unfit/limited/fit/none 四分支、断档=30 天的精确单位验证、到货感知模拟的逐批 used/end 断言、赠品三概念分离、localStorage 存取与 resetAll、40 组参数网格不变量）。

## 第五轮：区间化推荐去「一律合理」+ 数据保鲜 + 效期未知（同日）
用户指出 5 条，全部落地（`/tmp/t6.js`，**756 条断言通过**）：

1. **「合理购买区间」→ 三层结构**：① 撑到大促的最少 ② 提前囤货段（每多 1 套 = 提前囤约 X 天）③ 效期上限。落在 ② 时**必须有价格优势才成立**——新增「这次单价 vs 平时」下拉（不知道/明显更低/差不多/反而更高）：「明显更低」→ 绿色「有价格优势支持」；「差不多/更高」→ 橙色劝阻「只承担成本不产生收益」；「不知道」→ 蓝色中性并给出量化门槛（多占用资金按年化 3% ≈ 货价的 X%，低过这个折扣才划算）。「合理购买区间」字样已删除。
2. **赠品两种口径互斥**：同款 → 只把「会用掉的部分」并入可用量（进分母），**不再抵扣价格**；非同类 → 不进分母，只按主观估值抵扣成本（进分子）。明细始终单独显示「实际付款」（`listPrice`），不因估值而变。
3. **到货晚于大促 → 新增 kind='late'**：`shortBySale > maxNewBySale（=0）` 时直说「本单解决不了大促前的缺口，它只能为下一轮补货做准备」，并给出断档天数；此时不再输出「撑到大促 N 套」的区间。`minNeeded` 的口径改为 `needToSale − 旧货在大促前能消耗的量`（`oldBySale`），而非全程旧货消耗量。
4. **数据保鲜**：`persist` 记录 `savedAt`；重开页面显示「上次更新：X 天/小时/分钟前」，≥1 天时要求确认现有库存（[库存没变] / [我要改库存]）；`auditStale()` 自动把已过去的「大促日期」改成下一个 618/双11 并提示，已过去的到期日/到货日会点出来要求重选。
5. **效期未知模式**：新增「知道实际到期日 / 不知道（按假设估算）」下拉；选「不知道」时按「到货后 180 天」假设值计算，所有结论标注「按假设效期估算」，不再断言「不会过期」。**多批旧货**：可分别添加多批（数量 + 各自到期日），FIFO 模拟按批处理；未填则退化成「单一库存 + 最早到期日」。

细节：`derive()` 返回 `oldBatches`（多批）；`simulate` 探针计算 `maxNewBySale`（大促前新货最多能被消耗的量）与 `maxNoWaste`；面板高亮当前所在层（`.tier.cur`）；测试脚手架升级为 `/tmp/t6.js`（覆盖 5 条新逻辑 + 120 组参数网格不变量 + 390px 移动端截图验证三层面板/陈旧提示条/赠品口径说明）。

## 第六轮：多批旧货「草稿→确认接管」+ 问号提示 + 输入交互（同日）
用户指出 3 条，全部落地（`/tmp/t6.js` 787 条 + 新增 `/tmp/t7.js` 71 条断言，共 858 条通过）：

1. **「加一批旧货」清零库存 bug**：原 `derive()` 只要批次列表非空就替代单一库存，新批次数量为 0 → 库存瞬间变 0。改为**草稿/确认两段式**：新增 `useBatches` 标志，点「＋加一批旧货」只添加草稿行（第一次会把当前单一库存预填进第 1 批，便于拆分），页面上方库存仍是生效数字并显示「草稿·还没生效」徽标；填完点「✓ 就按这 N 批算（合计 X）」才接管。接管后上方库存框变为**只读的「各批合计」**（`k-stockRO`），`syncStateFromInputs` 加 `!s.useBatches` 守卫防止被覆盖成 0；删完全部批次自动退回单一库存；接管后合计为 0 会显式警告（不偷偷回退）。确认按钮文字由 `refreshBatchHints()` 实时刷新（不重画输入区，避免失焦）。
2. **长说明收进问号**：新增 `T(tip)` 组件 + 全局 `#tip` tooltip（悬停/点击/键盘聚焦均可展开；触屏上 tap 会先触发 mouseover 再 click，用 `hoverShown` 标记避免刚显示就被 click 关掉；点空白处/滚动时收起；在 `<summary>` 里点问号不会把 details 折叠）。主卡片说明、辅助区标题、三个辅助卡片 desc、比价/预售/拼单/赠品/多批旧货等十余处长文案全部改为 `?` 图标，版面明显变短；动态解释（如赠品口径）挂在 `#volTotal` 的问号上。
3. **数字输入交互**：
   - **滚轮**：全局 wheel 监听（passive:false）——数字框聚焦时可直接滚；未聚焦时把指针停在**右侧上下箭头区域**（right-22px）再滚也能加减，其余情况不抢页面滚动。
   - **滑块**：新增 `FS()` 组件（range + number 双控件双向同步，`bindRanges()`），用于 打算买几套（0–8 可增长：拖到头再拉 → max 翻倍）、每套份数/件数、每次用几份、一件能用几天、一瓶够用多少天、每天用多少 ml、赠品会用掉 %。滑块上限随预填值自动让开（避免滑块与数字框显示不一致）；非 grow 字段数字框带 max，grow 字段不带。
   - count 场景补了「≈ 每 X 天用 1 份」的动态换算提示。

**验证**：858 条断言（含：加批次后库存与结论不变、接管后 = 各批合计、接管后 sync 不清零、三场景接管、只读框渲染、滑块 min/max/step/value、预填超上限时滑块让位、长文案不再平铺但保留在 data-tip、滚轮仅在聚焦/箭头区生效、问号 tap/hover/收起时序、390px iframe 无横向溢出元素、tip 定位在视口内）。无头 Chrome 实测：点击加批次 → 草稿标记出现、库存仍为 6；填 5+15 → 按钮实时显示「合计 20 份」；确认 → 只读合计 20 份、可编辑框消失。
