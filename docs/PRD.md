# 囤货算盘 Stock or Stop — 产品需求文档

> 版本：v1.0 Final
>
> 对应成品：`index.html`
> 目标：开发者或 AI agent 仅凭本文，即可实现一份功能、口径、交互和视觉层级一致的纯前端产品。

## 1. 产品定义

### 1.1 一句话定位

囤货算盘是一款在大促下单前使用的本地计算工具。用户输入消耗速度、现有库存、套装规格、价格和日期后，产品回答：这次买几套能撑到下次大促，以及买到多少会在有效期内用不完。

### 1.2 目标用户

- 经常在直播间、618、双 11 购买大包装或多件套的消费者。
- 购买面膜、护肤品、洗护用品、纸品、猫粮等稳定消耗品的人。
- 想拼单，但不想平均分货和平均分账的人。
- 对价格敏感，同时担心过期、占空间和冲动购买的人。

### 1.3 核心问题

普通比价只回答“每件多少钱”，无法回答“我实际能用掉多少”。标价便宜的商品若大量过期，实际单位成本反而会升高。产品必须同时计算：

1. 每天消耗多少。
2. 家里已有多少，以及这些货何时到期。
3. 新货什么时候到、什么时候到期。
4. 一套包含多少可用量，用户准备买几套。
5. 下次大促前是否断档。
6. 有效期内是否能用完。

### 1.4 产品边界

必须：

- 纯 HTML、CSS、JavaScript；单文件可直接打开。
- 不联网、不上传数据、不依赖后端或 AI。
- 使用 `localStorage` 自动保存输入。
- 支持按次、按体积、按件三种模型。
- 提供主决策、套装比价、拼单分摊三个能力。

不包含：

- 商品搜索、价格抓取、扫码、订单导入。
- 平台优惠券、满减、运费算法。
- “预售 vs 现货”独立模块；到货等待已并入主流程。
- 账户、云同步、服务端存储。
- 绝对的“值得买”推荐。

## 2. 核心概念

### 2.1 三种场景

| key | 名称 | 单位 | 典型商品 | 每天消耗量 |
|---|---|---|---|---|
| `count` | 按次用 | 份 | 面膜、一次性用品 | 每次用量 ÷ 间隔天数 |
| `volume` | 按体积用 | ml | 护肤、洗发水 | 每天 ml，或瓶容量 ÷ 使用天数 |
| `pack` | 按件用 | 件 | 洗衣液、纸品、猫粮 | 1 ÷ 一件使用天数 |

全部归一为 `rate`、`stockAmount`、`setAmount`、`U`，后续共用同一个模拟器。

### 2.2 两个“剩余”

- 下次大促时还剩：货仍有效，只是提前购买并占用资金、空间，不等于损失。
- 到期时还剩：有效期内预计用不完，是直接浪费，并计入实际成本。

判断“囤过头”只使用“到期时还剩”。

### 2.3 三段购买区间

| 区间 | 颜色 | 含义 |
|---|---|---|
| 撑到下次大促的最少 | 绿 | 覆盖至下一次大促的保守数量 |
| 提前囤货段 | 橙色斜纹 | 能用完但提前占钱和空间，需要价格优势 |
| 有效期上限 | 红 | 超过后预计产生过期浪费 |

区间条必须有完整圆角。三色块放入带 `overflow:hidden` 的内层 `.zones`；游标放在外层，避免破坏右端圆角。

### 2.4 赠品口径

同款或通用赠品：

- 填赠品总量和预计用掉比例。
- 预计用掉的赠品并入 `setAmount`。
- 不再抵扣价格，防止重复计算优惠。

非同款赠品：

- 不并入正装可用量。
- 此时才显示“赠品估值”。
- 估值只从成本分子扣除，不改变实际付款。

即：同款赠品进分母，非同款赠品进分子，两者互斥。

1. 主流程 `#sec-main`

## 4. 主流程输入规格

### 4.1 场景切换

三张等宽卡片：按次用、按体积用、按件用。当前卡使用橙色边框和浅橙背景。每个场景独立保存状态，切换不丢数据。

### 4.2 使用情况

按次用：

- 多久用一次：数字框 + 天/周。
- 每次用几份：滑块 + 数字框。
- 家里还有：数字框。

按体积用：

- “按一瓶 / 按每天”分段选择。
- 按一瓶：瓶容量、一瓶使用天数。
- 按每天：每天使用 ml。
- 家里还剩：数字框 + ml/瓶切换。

按件用：

- 一件能用几天：滑块 + 数字框。
- 家里还有：数字框。

滑块统一结构：标签与紧凑数字框同一行；中间全宽轨道；下方最小/最大刻度。备注使用常规字重。

### 4.3 这次想买的套装

按次/按件：

- 每套份数或件数。
- 套装到手价。
- 计划买几套。
- 这次单价 vs 平时：未比价、更便宜、差不多、更贵。

按体积：

- 套装规格按“容量 × 数量”多行录入。
- 赠品总量、预计用掉比例。
- “能合并 / 不能合并”分段选择。
- 不能合并时才出现赠品估值。
- 套装到手价、计划买几套、价格对比。

适合试算的数量和比例使用滑块；价格、容量、日期用 36px 左右的紧凑输入框。

### 4.4 关键日期

- 下次大促默认最近的未来 618 或双 11。
- “有效期、到货与多批库存”默认折叠。
- 新货有效期可选知道/不知道。
- 不知道时按到货后 180 天估算，并标注“估算”。
- 预计到货日。
- 家里旧货最早到期日。

### 4.5 多批库存

采用草稿确认机制：

1. 新增批次不立即覆盖主库存。
2. 填写每批数量、到期日。
3. 点击确认后 `useBatches=true`。
4. 上方库存显示批次合计且只读。
5. 删除所有批次后回到单一库存。

这避免用户添加空白批次时库存瞬间归零。

## 5. 计算引擎

### 5.1 日期

日期统一转成距本地今天零点的天数。过去的大促日期自动顺延；过去的到货/到期日期提示重选。

### 5.2 批次模型

```js
{
  id: string,
  units: number,
  start: number,
  expiry: number,
  used: number,
  waste: number,
  end: number
}
```

旧货 `start=0`；新货 `start=预计到货天数`。

### 5.3 `simulate(batches, rate, cap?)`

规则：

1. 只消费已到货、未过期、有余额的批次。
2. 优先消费最早到期者；同到期日按到货时间。
3. 当前无货时跳到下一批到货日，空窗视为断档。
4. 下一事件为：当前批次用完、到期、新批到货或观察窗口结束中的最早者。
5. `cap` 用于观察某天剩余量，必须运行同一算法，不得按比例缩放。
6. 返回每批 `used/waste/end`、总使用、总浪费和 `remainingAt(day)`。

浮点容差 `EPS=1e-6`。

### 5.4 公式

```text
needToSale       = saleDays × rate
oldBySale        = 旧货在大促前实际用掉量
shortBySale      = max(0, needToSale - oldBySale)
setsBySale       = ceil(shortBySale / setAmount)
maxNoWaste       = 用无限新货探测出的到期前最大可消耗量
maxSetsNoWaste   = floor(maxNoWaste / setAmount)
plan             = planSets × setAmount
leftAtSale       = 计划方案在大促日的剩余量
leftAtEnd        = 计划方案最终浪费量
effectiveCost    = 本次新货成本 / 本次新货实际用掉量
```

非同款赠品时，成本分子为“实际付款 - 赠品估值”；实际付款仍原样展示。

### 5.5 结论类型

| kind | 条件 | 标题 |
|---|---|---|
| `none` | 旧货已能撑到大促 | 这次可以不买 |
| `late` | 有缺口但新货赶不上 | 本单赶不上大促 |
| `unfit` | 连一套都用不完 | 规格不适合，别按这套买 |
| `limited` | 所需套数超过效期上限 | 有效期内最多买 N 套 |
| `fit` | 其余情况 | 按计划档位展示 |

计划档位：

- `empty`：未填购买套数。
- `short`：低于保守套数。
- `just`：等于保守套数。
- `ahead`：高于保守套数但未超过有效期上限。
- `over`：超过有效期上限。

`ahead` 必须结合价格对比：更便宜可提前囤；未比价先提示比价；差不多或更贵则建议停在保守下限。

## 6. 结果区

桌面端左侧输入、右侧结果，顶部对齐。右栏在宽屏下 sticky 并可独立滚动。

### 6.1 深色结论卡

首屏展示：

- 一句大结论。
- 一行短理由。
- “下次大促时还剩”“到期时剩”两个指标。
- 实际单位成本。
- 新货到期前可用比例。

深色卡与下方白色区间卡直接相连，中间不得露灰底。

### 6.2 区间卡

- 标题“买几套合适”。
- 绿、橙色斜纹、红三段条。
- “你：N 套”游标。
- 三条短图例和一行保守结论。

### 6.3 计算依据

默认显示四步摘要：每天用多少、家里还有多少、这次买多少、到期前能用多少。完整数字放入折叠区，不重复深色卡长结论。

### 6.4 Tooltip

问号支持悬停、点击、键盘聚焦。最大宽度 280px，内容使用短句并主动换行；滚动、失焦或点击空白处关闭。

## 7. 套装比价

输入方案名称、到手价、等效总量、新货有效期。支持新增、删除。

每个方案与主流程共用当前场景单位、消耗速度、旧货批次和 FIFO 模拟。

```text
实际单位成本 = 到手价 / 到期前实际能用掉的量
```

列表展示到手价、等效总量、能用掉量、实际单位成本；最优方案浅绿色高亮。不得只按标称单价排序。

## 8. 囤货拼单分摊

### 8.1 顶部

桌面为左右等宽两栏：

- 左：规格清单，每套件数/容量、数量滑块、删除、新增规格。
- 右：整单概览，整单到手价、总可分量。

两栏标题和首行控件对齐。数量为滑块 + 紧凑数字框。

### 8.2 成员与分账

输入昵称、需要量和单位。体积场景支持 ml/瓶。

成员表格：成员、需要、占总量、应摊货款、删除。前四列均分，删除列固定窄宽；叉号水平、垂直居中。

```text
total       = Σ(规格量 × 数量)
avg         = 整单价 / total
memberPay   = memberNeed × avg
share       = memberNeed / total
unclaimed   = max(0, total - ΣmemberNeed)
```

汇总为三个等宽卡片：整单、已分给成员、每单位均价。未分配使用低强调灰底短句；超额认领使用警告态。

## 9. 计算方法

标题和卡片与上方模块共用 1200px 版心。桌面两列，移动端一列，只保留：

1. 消耗顺序。
2. 到货等待。
3. 多批库存。
4. 套装比价。
5. 同款赠品。
6. 非同款赠品。

不设内部一级标题，不重复解释购买区间。

## 10. 视觉与响应式

- 页面冷灰蓝背景，卡片白色。
- 橙色只用于主要按钮、当前选择、滑块。
- 藏蓝用于核心结论；绿色用于安全/最优；红色用于风险。
- 系统中文无衬线字体；输入文字与正文协调。
- 输入高度约 36px。
- 避免卡片内部继续嵌套重边框。
- 备注使用常规字重。
- 主内容最大宽度 1200px。
- 主流程 1020px 以上双栏，以下单栏。
- 拼单顶部、计算方法在 700px 以下单栏。
- 390px 宽度不得横向溢出。
- 页脚只保留“数据保存在本机，刷新或重开仍在”。

## 11. 本地数据

`localStorage` key：`stockpile-demo-v1`。保存版本、场景、三个状态、比价方案、比价修改标记和保存时间。

恢复时合并默认值以兼容旧字段；超过一天提示确认库存；过去的大促日自动顺延。

“清空重填”删除该 key，恢复三个场景默认值、比价示例和拼单状态。

## 12. 示例

默认场景为按次用。三个场景均需合理默认值，使首次打开即可看到结论。载入示例使用居中 dialog：先选场景，再选案例。至少覆盖复购、提前囤货、规格不适合、临期浪费。日期必须运行时生成。

## 13. 无障碍

- 问号：`role="button"`、`tabindex="0"`、`aria-label`。
- 分段按钮：`aria-pressed`。
- 滑块：与标签一致的 `aria-label`。
- 所有按钮可键盘聚焦。
- 数字框支持键盘、滚轮、滑块；滚轮不能抢页面正常滚动。

## 14. 验收清单

功能：

- [ ] 三场景独立保存。
- [ ] ml/瓶切换保持物理量不变。
- [ ] 多批库存确认前不接管、确认后按合计。
- [ ] 同款/非同款赠品互斥。
- [ ] 到货前不能消费新货。
- [ ] 始终优先消耗最早到期批次。
- [ ] 两个剩余来自同一模拟器。
- [ ] 改计划套数后即时更新。
- [ ] 比价按实际可用量排序。
- [ ] 拼单金额满足公式。
- [ ] 清空恢复默认。

视觉：

- [ ] 主流程左右顶部对齐。
- [ ] 深色卡与区间卡无灰缝。
- [ ] 区间条两端圆角完整。
- [ ] 输入高度、字体、颜色统一。
- [ ] 拼单顶部左右等宽对齐。
- [ ] 成员删除叉居中。
- [ ] 计算方法同版心、两列六项。
- [ ] Tooltip 简短且不溢出。
- [ ] 390px 无横向溢出。

算法：

- [ ] `used + waste = units`，容差 `1e-6`。
- [ ] 保守套数向上取整。
- [ ] 有效期上限套数向下取整。
- [ ] `newUsed ≤ plan`。
- [ ] 无实际使用量时不显示有限实际单价。
- [ ] 效期未知时标注估算。
