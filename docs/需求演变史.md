# 需求演变史（逐轮）

> 本文档记录「囤货算盘 Stock or Stop」从脑图到成品的**每一轮用户反馈 → 需求 → 实现**。
> 读它不是为了照抄，而是为了理解 **§为什么这么设计**。PRD 里的每一条硬性规定，几乎都对应这里一次踩坑。

---

## 第 0 轮 · 起点：一张脑图，六个模块

**输入**：用户给出一张「囤货需求」脑图（比价 / 预售 / 囤货必要性 / 临期 / 拼单 / 资金成本）。

**产出**：纯前端单文件 demo，6 个模块：

1. 真实单价比价（含小样折算 + 机会成本开关）
2. 预售 vs 现货
3. 囤货规划器（补货日 / 最优囤货量 / 过期成本）
4. 临期捡漏
5. 拼单分摊（满减 + 运费分摊）
6. 资金机会成本

**问题**：模块平铺，**主次不分**——用户来是为了「这次买几件」，但页面像 6 个并列的小工具。

---

## 第 1 轮 · 明确主任务，分开两类「剩余」

**用户反馈**：
> 产品主次不分，需要明确的主任务与核心流程；比价/预售/拼单降为辅助；资金机会成本降为折叠说明；临期不单列。
> 要**分开**「下次大促前没用完」（占钱占空间，未必亏）和「过期浪费」（真损失）。
> 两处会误导判断的 bug：[line 403] 旧货效期被当新货效期；[line 408/432] ceil / floor 不一致。

**需求**：

1. 首屏唯一主流程 = 「这次买几件合适，会不会囤过头」。
2. 输出分开两个量：大促时还剩（提前占用） / 到期时剩（硬损失）。
3. 修两个口径 bug。

**实现**：

- 主流程输入收敛为：库存件数 + 一件用多久 + 套装件数/价格 + 计划买几套 + 旧货到期日 / 新货到期日 / 下次大促日期。
- 旧货与新货效期**分开输入**。
- 推荐量改走**同一套 FIFO 消耗模拟**，消除 ceil/floor 矛盾。
- 新增核心引擎 `simulate(batches, r)`：按最早到期优先做连续时间消耗模拟。
- 资金机会成本降级为主结果里的 `<details>` 折叠（默认年化 3%）。
- 临期场景并入主流程（= 新货效期很短）。
- 验证：192 组参数组合不变量断言全过。

---

## 第 2 轮 · 三场景消耗模型

**用户反馈**：
> 「一件用多久」的表述对护肤套装不适用（多毫升组合怎么算「一件」？）；预售 vs 现货数据调整不方便且无联动；下次大促日期最好默认填 618 / 双 11。

**需求**：

1. 按消耗方式分场景。
2. 预售 vs 现货做成双栏卡片并与主流程联动。
3. 大促日期默认下一个 618 / 双 11。

**实现**：

- **三种消耗模型**（各自独立输入、独立保存 `state[scene]`）：
  - `count` 按次用（面膜）：多久用一次 × 每次几份
  - `volume` 按体积用（护肤）：每天 ml + **套装按「容量×数量」多行录入** + 赠品折算率，自动合计每套等效 ml
  - `pack` 按件用（洗衣液）：一件用 N 天
- 统一归一到「每天消耗量 / 库存量 / 每套量」，复用同一 `simulate()`。
- 每个场景 2 个示例按钮；比价示例随场景切换。
- `nextSale()`：6-18 → 11-11 → 次年 6-18，取最近未来节点。
- 预售 vs 现货改双栏卡片，默认联动（现货=主流程套装；预售=9折+等15天+赠品20元），改动某栏即置「已手动调整」并停止跟随，可一键恢复。
- **修 bug**：`minNeeded ≤ 0.05` 的容差对离散单位（件）太松（「1 件用 30 天 vs 大促 31 天后」被误判「不用买」），收紧到 `1e-6`。
- 测试扩展到 3 场景 × 参数网格（192 组）。

## 第 3 轮 · 体积场景可倒推 + 拼单改为囤货分摊

**用户反馈**：
> 按体积用的部分，「一次用几毫升」消费者没概念，应该**倒推**（按「一瓶 ml 够用多少天」）。「下次大促时还剩几毫升」最好用「几分之几瓶」表达。拼单针对的是**囤货场景下的拼单**，而不是电商购物车满减。

**需求**：

1. 不让用户估「每天几 ml」，改为从已知信息倒推。
2. 结果用「几分之几瓶」表达。
3. 拼单改为「囤货大单按需分摊」。

**实现**：

- `rateMode` 开关：默认「我知道一瓶能用多久」（填 一瓶 ml + 够用天数 → 自动算 ml/天并回显）；另一档「我知道每天用多少」。
- 库存支持**瓶 / ml 双单位**（切换保持物理量不变），按「最大正装 ml」给出「≈N 瓶」提示。
- 结果双口径：`amtRef()` → 「1200 ml（≈2.4 瓶）」；小数量用分数（1/2 瓶、1/3 瓶…）；小于 0.1 瓶不换算（避免「0.04 瓶」）。
- **拼单重做**：删掉满减/免邮。新模型 = 一大单买回来（规格 × 数量，默认沿用主流程套装 × 计划套数），几个朋友按各自真正需要的量分摊，忽略邮费。输出每人需要量、占比、应摊货款，并提示「未被认领的余量」或「超额认领」。
- **顺带修 bug**：`remainingAt(D)` 原各批独立按 `start` 计算，忽略 FIFO 占位 → 出现「到期剩 > 大促剩」。改为**用同一套 FIFO 规则把时间轴截到 D 重算**。
- 测试 605 条断言全过。

## 第 4 轮 · 四个逻辑问题 + 两个产品风险

**用户反馈**：逐条指出 4 个逻辑问题 + 2 个产品风险。

**逻辑修复**：

1. **推荐整套却会过期** → 推荐量在「套」层对齐（`maxSetsNoWaste = floor(上限/每套量)`、`minSetsNeeded = ceil(下限/每套量)`），引入四种 `kind`（`none/fit/limited/unfit`）；`maxSetsNoWaste===0` 判为 `unfit`，明确输出「规格不适合」，绝不把 1 套标成建议量。
2. **断档天数单位错**（把「缺几件」当天数） → 改为 `gapDays = ceil(sale − usedBySale/r)`，加 `1e-9` 容差避免浮点误报 1 天。
3. **到货时间模拟有风险** → `simulate()` 重写为**事件驱动、到货感知**：只从「已到货且未过期」的批次消耗；未到货不能提前用。主流程新增「预计到货日」。修掉「新货效期比旧货早时，预售断档被误判 0 天」。
4. **赠品「价值」与「实物量」混在一起** → 体积场景赠品拆成 4 个输入：实收 ml / 预计用掉 % / 能否与正装合并 / 估值 ¥（只抵成本 → 净价 = 到手价 − 估值）。

**产品风险**：

5. **语气去断语** → fit 时输出「合理购买区间：X ~ Y（N ~ M 套）」+ 取舍说明，不说「刚好合适 / 建议买 N 套」。
6. **首屏减负 + 本机持久化** → localStorage（`stockpile-demo-v1`）保存 `mode/state/offers`，刷新还在；示例按钮提前；输入分三组；效期/到货收进折叠；新增「清空重新填」。

**移动端**：发现无头 Chrome 有 500px 最小窗宽（截图假象），改用 390px iframe 验证。顺手把表格包进 `.tbl{overflow-x:auto}`。

**验证**：`t5.js` 281 条断言全过。

## 第 5 轮 · 区间化推荐去「一律合理」+ 数据保鲜 + 效期未知

**用户反馈**（5 条）：

1. 「不过期上限」被称为「合理购买区间」的上限，是误导——「不过期就能用」≠「应该买」。
2. 赠品仍可能被重复算作优惠。
3. 推荐套数尚未受「到货晚于下次大促」约束。
4. 本机保存后数据会变旧。
5. 效期被折叠且预填「典型值」，用户可能根本不知道实际效期。

**实现**：

1. **「合理购买区间」→ 三层结构**：① 撑到大促的最少 ② 提前囤货段 ③ 效期上限。落在 ② 时**必须有价格优势**——新增「这次单价 vs 平时」下拉：「明显更低」→ 绿色支持；「差不多/更高」→ 橙色劝阻；「不知道」→ 中性 + 量化门槛（年化 3% ≈ 货价的 X%）。删除「合理购买区间」字样。
2. **赠品两口径互斥**：同款只进分母、非同类只进分子，「实际付款」恒定单独显示。
3. **新增 `kind='late'`**：到货晚于大促时直说「本单解决不了大促前的缺口」；`minNeeded` 口径改为 `needToSale − oldBySale`。
4. **数据保鲜**：`persist` 记 `savedAt`；重开显示「上次更新：X 前」，≥1 天要求确认库存；`auditStale()` 自动把已过去的大促日期改成下一个 618/双11，已过去的到期/到货日点出要求重选。
5. **效期未知模式**（按「到货后 180 天」假设，结论标注估算）+ **多批旧货**（分别填数量 + 到期日，FIFO 按批处理）。

**验证**：`t6.js` 756 条断言通过。

## 第 6 轮 · 多批旧货「草稿→确认」+ 问号提示 + 输入交互

**用户反馈**（3 条）：

1. 点「加一批旧货」，尚未填数量时，原库存瞬间变成零。
2. 大量解释性描述可以变为问号 icon。
3. 手动输入数字或按上下键加减有点麻烦（滚轮）。

**实现**：

1. **草稿/确认两段式**：新增 `useBatches` 标志。点「＋加一批旧货」只加草稿行（第一次预填当前库存进第 1 批）；库存框仍是生效数字 + 「草稿·还没生效」徽标；填完点「✓ 就按这 N 批算（合计 X）」才接管。接管后库存框变只读合计，`syncStateFromInputs` 加 `!s.useBatches` 守卫防止被覆盖成 0；删完批次自动退回单一库存；接管后合计为 0 显式警告。按钮文字由 `refreshBatchHints()` 实时刷新（不重画输入区避免失焦）。
2. **长说明收进问号**：新增 `T(tip)` + 全局 `#tip`。悬停/点击/键盘聚焦均可展开；触屏 tap 先 mouseover 再 click 的时序用 `hoverShown` 标记解决；点空白/滚动收起；summary 内点问号不折叠。
3. **数字输入交互**：全局 wheel（passive:false）——聚焦时可滚，未聚焦时指针在右侧箭头区（right-22px）可滚；新增 `FS()` 滑块组件（range + number 双向同步）。
4. （此轮 `FS` 还带「拖到头自动翻倍」的 grow 机制，后被第 8 轮移除。）

**验证**：`t6.js` 787 条 + `t7.js` 71 条 = 858 条断言全过。

## 第 8 轮 · 滑块 UI 重构

**用户反馈**：
> 想做「下方滑块、左上指标名、右上数字+上下键」的 UI。且现在的滑块一旦滑到最右，想再划回来非常容易一下从 1 变到 2000，失去滑块意义。打算买多少可以设滑块上限（如 20），想突破 20 可通过手动输入。

**实现**：

- `FS()` 重写为三层布局：上行 = 指标名 + 数字框（右上），中行 = 全宽滑块，下行 = min/max 刻度。
- **移除 grow 翻倍机制**：滑块上限固定 cap（`planSets=20`、`setSize=30`，其余=原 max）；超上限走数字框手动输入（number 保留 `max` 属性钳住滚轮/上下键，但键入不受限）。
- 值超 cap 时滑块钉最右、右刻度变橙 `20+套`，加 `.over` 高亮。
- 各字段加单位刻度（份 / ml / 天 / 套 / %）。

**验证**：`t7` 更新第 4 节断言（75 通过），`t6` 787 通过；`probe8` 11 条交互全 PASS。

## 第 9 轮 · 口径统一（比价 / 预售沿用主流程模拟器）

**用户反馈**：
> 「套装比价」用「旧货用完日 → 新货到期日」的简化窗口，没有沿用主流程的多批次、到货时间和先到期先用规则；「预售 vs 现货」还把旧货的「用完日」当「到期日」。因此同一候选商品可能在主流程显示可用，在比价区却被判为浪费。
> 另外 UI 上结论太难扫读（像一份计算报告），建议电脑端左右分屏；降低重复强调（橙色标题/滑块/边框/彩色结论框同时抢注意力）；保留橙色给主要操作和当前选择，风险用红，普通解释用中性色；顶部导航栏用页面切换；产品名「囤货算盘 / Stock or Stop」+ logo。

**实现**：

- **口径统一**：`LAST` 快照带上真实旧货批次 `oldBs`；套装比价与预售比较都改为 `simulate(oldBs.concat([新货]), r)`，与主流程**同一个模拟器、同一批旧货数据**。
- **UI 重构**：单页 + 顶栏导航锚点滚动；新增 Hero；去框嵌框；左右分屏；右侧深色结论卡；三层推荐改区间条可视化；「两个数字区别」变问号 tooltip；计算明细默认展开浅色小字；资金机会成本折叠删除。
- 产品名与 logo 落地。

**验证**：869 条断言通过；`probe10` 20/20。

## 第 10 轮 · 定稿 UI（锚点导航 + Hero + 深色结论卡 + 区间条）

**用户反馈**：
> 顶部导航栏为**导航**作用，而不是页面切换；页面里不要一个框嵌套一个框；最顶部首屏参考图1，往下滑参考图2，背景底色拉通；主流程右侧结论文字太多太冗余（要么可视化、要么精简到几个关键词），重点结论框为深色白字、重点结论放大字体；目前左右两个框没对齐，需要对齐；计算明细可以默认展开，字体及颜色浅一点；「这两个数字有什么区别」作为问号 icon 点击悬停展开，放到上方大结论处；「补充：这批货的年化成本」直接删除。

**实现**：

- 单页化：顶栏导航改为**锚点滚动** + `IntersectionObserver` 高亮。
- Hero 首屏全幅拉通。
- 去框嵌框（`.box/.hint/.sub-grid/.presetbar` 扁平化）；预售区拆两张平级卡。
- 右侧结论面板重做：深色渐变卡白字大结论 26px + 关键词副行 + 半透明指标瓦片 + 「到期前能用掉」进度条；三层推荐改区间条 + 游标 + 三行图例；「两个数字区别」变深色卡问号 tooltip；计算明细默认展开浅色小字，长解释下沉到明细「结论说明」；资金机会成本折叠删除。
- 修 `unfit` 时高亮落在第 ③ 层；区间条 `z3=0` 时补一截红色提示区。
- 修导航高亮 `rootMargin` 参数（hash 直达时检测不到）。
- 左右分屏顶对齐 + 右栏 sticky。

**验证**：`t6` 787 + `t7` 82 全过（补 `IntersectionObserver` 桩）；`probe10` 20/20；桌面/移动/囤过头/预售区截图确认。

## 一句话总结这条演进路径

> **从一个「六模块工具栏」，收敛为「一个主问题 + 三个辅助工具」；从「比价」收敛为「买几件的量」；从「一律合理」收敛为「三层区间 + 条件」；从「各算各的」收敛为「同一个模拟器」；从「报告式长文」收敛为「结论可视化 + 解释下沉」。**
